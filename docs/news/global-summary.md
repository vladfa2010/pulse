# Global AI Summary (Обзор рынка)

## Эндпоинт

`GET /api/user/summary-global`

Требует авторизации (`authMiddleware`). Параметр `?refresh=1` запускает принудительную перегенерацию общего кэша.

## Логика

- Возвращает AI-саммари по **всей новостной ленте** за последние **6 часов**.
- Источник: таблица `news`, без фильтра по тегам, сентименту, политике или типу статьи.
- В промпт попадает до **200** последних новостей (`ORDER BY published_at DESC LIMIT 200`).
- Кэш **общий для всех пользователей** (in-memory), TTL = **6 часов + 10 минут** (покрывает retry-окно при timeout 180 сек).
- In-flight дедупликация: параллельные запросы ждут одну генерацию.

## Обновление

- **Крон**: раз в 6 часов в 00:00/06:00/12:00/18:00 МСК (`0 */6 * * *`, timezone `Europe/Moscow`).
- **Первый прогрев** через 3 минуты после старта сервера.
- **Ручное обновление**: кнопка «Обновить» у любого залогиненного пользователя.
- **Rate-limit на refresh**: 1 запрос в 5 минут на пользователя → `429`.

## LLM

- Provider: Kimi API (`https://api.moonshot.ai/v1/chat/completions`).
- Модель: `process.env.KIMI_MODEL`, default `kimi-k2.6`.
- Timeout: **180 секунд**.
- Промпт включает anti-injection инструкцию: LLM игнорирует команды внутри текстов новостей.
- При отсутствии `KIMI_API_KEY` возвращается fallback-текст (не кэшируется).
- **ТЗ-50: диагностика** — любой отказ LLM логируется с телом ответа: `[GlobalSummary] LLM error: ... status: N body: {...}` (до 500 символов). Раньше `err.message` терял причину 400 от Moonshot.
- **ТЗ-50: авто-деградация при 400** — один ретрай с ужатым промптом: первые 80 статей, `title`/`summary` обрезаны до 120 символов, строка «Теги:» исключена. Повторный SQL не выполняется. Если ретрай тоже падает — его body логируется отдельной строкой (`LLM retry error`).

## Безопасность и надёжность

- Распределённый лок `cron_locks` (job_name = `global-summary`) предотвращает параллельный запуск крона на нескольких инстансах.
- При LLM timeout/network error крон делает **один retry** через 60 секунд.
- Ошибки крона пишутся в `cron_log` с `task_name = 'global_summary'`.
- **ТЗ-50: stale-fallback** — если генерация упала окончательно (400 после ретрая, timeout, сеть), а в кэше есть запись любой давности, роут отдаёт её со `stale: true` вместо 500. `generated_at` показывает возраст обзора.

## Формат ответа

```json
{
  "summary": "…",
  "cached": true,
  "generated_at": "2026-09-04T00:00:00.000Z",
  "articles_count": 200,
  "stale": true
}
```

`stale` присутствует только при отдаче кэша после неудачной генерации; фронт его не обрабатывает специально — старый обзор лучше ошибки.
